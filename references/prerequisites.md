# 材料与依赖前置检查

先盘点材料，再检查所选路线需要的能力。检查脚本**只读取运行条件和测试输入**，
不安装、不下载、不上传。

---

## 先核对材料是否属于同一段内容

检查视频时长、字幕覆盖范围、语言和版本，抽看开头 / 中间 / 结尾的对应关系。

- **全场字幕可能搭配截断视频**——不能把媒体范围之外的字幕塞进最后一页。
  只使用能对应当前视频的范围；边界跨句时核对词时间或回听。
- **保留原字幕，裁选结果另存并记录范围**。
- **原 PPT 页数也不等于视频实际讲到的次数**——页数是"讲过几页"，不是"拿到几页"。

---

## 音视频分离是常态，要分别处理

很多来源给的是**一条无声画面 + 一条纯音频**，而不是一个文件：

| 来源 | 形态 |
|---|---|
| YouTube 高清（走 DASH 分流） | 视频流与音频流**分开**下载，各自成文件 |
| 部分录屏 / 剪辑工具 | 导出时可选"仅视频""仅音频" |
| 直播回放抓流工具 | 常按流分别落盘 |

**处理原则**：

1. **两条时间轴必须对齐**。抽页用画面那条、转写与音轨扫描用声音那条；
   先核对**两条的时长差**（实测一例差 0.08 秒，可忽略；差得多就要查是不是截断过）。
2. **`preflight.py` 分别传**：`--video-file` 查画面、`--audio-file` 查声音。
   只给 `--media` 时按单文件处理。
3. **记下来源是分离的**——转写产物里的 `manifest.json` 要能看出画面与声音各来自哪个文件，
   否则日后复现时不知道时间轴以谁为准。

> ⚠️ 把一个只有画面的文件丢给转写、或把纯音频丢给抽页，**两边都会失败**，
> 而且报错不会告诉你"你拿错了文件"。所以这一步先做。

## 按需检查表

| 要做什么 | 必需条件 | 验证方式 |
|---|---|---|
| 文字整理与差异报告 | 能理解材料的 AI 环境；Python 3.10+；可读文字和可写输出目录 | Python 实际运行；输入编码 / 正文结构可读；输出目录创建临时文件后删除 |
| 视频抽页、扫描、裁片 | `ffmpeg`、`ffprobe`；可解码视频 / 音轨 | 读取媒体信息并**解码短视频 / 音频样本** |
| 本地听写 | 上述媒体工具；`whisper-cli`；兼容模型文件 | 先检查路径与退出状态；**再用真实短音频加载模型并听写**，成功后才跑全段 |
| 在线材料获取 | 当前网站可用的授权下载 / 浏览器能力 | 先验证链接和访问，按需检查下载工具 |
| PPT / PDF 变图片 | 当前环境支持该格式的渲染工具 | 先转换**一页**并检查图片清晰度 |
| 看图与回听 | 当前 AI 工具实际支持图片 / 音频检查 | 用小样验证；不支持时说明**哪些质量检查未完成** |

### 检查脚本

```bash
# 只查 Python / 输出目录 / 磁盘
python3 <SKILL_DIR>/scripts/preflight.py --out-dir <输出目录>

# 单文件（画面与声音在同一个文件里）
python3 <SKILL_DIR>/scripts/preflight.py --media talk.mp4 --video --out-dir <目录>
python3 <SKILL_DIR>/scripts/preflight.py --media talk.mp4 --asr --model <模型> --out-dir <目录>

# 音视频分离
python3 <SKILL_DIR>/scripts/preflight.py \
    --video-file video.mp4 --audio-file audio.mp3 \
    --video --asr --model <模型> --out-dir <目录>
```

它检查 Python、目录可写、命令**实际启动**、媒体信息、**短样本真解码**；
`--asr` 还检查模型可读且非空。需要听写时，再用
`local_asr.py transcribe ... --duration 15` 确认模型**能实际加载并生成文字**——
静音开头要换有人说话的片段。

**超时给足**：`--tool-timeout` 默认 60 秒。机器被别的重任务占满时，
一次 `whisper-cli --version` 可能要 20 秒以上；卡太紧会把"机器忙"误报成"工具坏了"。

参数可显式给工具路径；模型也可通过 `LOCAL_ASR_MODEL` 提供。工具路径由当前环境确定，
**记录实际使用的 Python 与工具位置**。报告列出通过项、影响当前路线的缺项、以及下一步。

## 缺依赖怎么办

先查当前环境**已有工具和等价能力**。需要安装或下载时，说明名称、用途、来源与体积；
遵循已有授权和系统权限，**不重复索取已给的批准**。

> **没有授权时，不要静默下载大型模型**，也不要擅自改用收费服务或上传用户视频。
> 继续做不依赖该工具的工作。

转写安装参考官方 whisper.cpp 项目：<https://github.com/ggml-org/whisper.cpp>。
模型使用其官方说明指向的来源；下载前确认平台、模型语言、存储和内存条件。
**若来源提供可信校验值，下载后比对；仅自行计算哈希只能用于后续识别文件，
不能宣称"已验证来源"。**

按当前操作系统选择工具。命令启动失败时**查明错误**，再修复或选等价工具；
GPU 失败时可**明确**改用 CPU（不要静默降级）。
