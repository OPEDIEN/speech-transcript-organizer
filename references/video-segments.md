# 演示、配音与异常片段的判定与裁切

演讲里常夹着**播放的演示视频**（有时演讲人一边放一边讲）。这些段落抽页时不是幻灯片、
转写时没有正常语音，**不主动找就会漏**：裁不出片段，整理时也不知道该怎么写。
视频越长越容易漏——几十分钟的片子没人愿意逐段听。

本文件说三件事：**先扫一遍音轨**、**两个判断**（有没有独立画外音 / 裁什么范围）、
**要裁时的做法**。

---

## 先扫一遍整条音轨，别靠逐段听

用脚本把候选段连证据一起列出来：

```bash
python3 <SKILL_DIR>/scripts/scan_segments.py <视频> \
        --segments <转写目录>/segments.json --out <输出目录>/音轨扫描.json
```

它用 ffmpeg `astats` 逐帧（约 21ms）算 RMS，按「能量 + 停顿结构」把时间轴切成
**人声 / 恒定能量 / 静音**，并**自动把转写稿在同一时间窗的文本附上**——
也就是「判断一」要的两个证据，一次给全。

**没有时间分段文件时省略 `--segments`，不能伪造对应关系。**
该文件必须与视频使用**同一时间基准**。

它给的是**候选，不是结论**：扫描按能量和停顿找可疑段，**不识别人声身份，也不证明哪段是演示**。
候选段要回听确认；判断结果要**主动告诉用户并说明依据**。

> **字幕空白也可能是漏听**；**连续能量下既可能有配乐，也可能有配乐上的真实人声**。
> 不能直接删掉「可疑」文本；**无法回听时把结论标为未验证**。
> 保留原转写、修订另存，记录删除的范围和理由。
> 发现疑似漏转写时**重查该段**，而不是凭上下文补写。

### 判据为什么是「停顿结构」

实测同一场里，配乐段的 RMS 动态范围约 **19 dB**，人声段约 **52 dB**：
配乐长时间不落到静音，人声每几秒就有一次句间停顿。两者区分度很高。

> ⚠️ **但这个区分度依赖录音自身的动态范围，不是普适常数。** 音频被压过的直播流上，
> 人声段动态范围可能只有 40 dB，与恒定能量段的 29 dB 几乎重合——这时**任何静音门限都分不开**
> （实测某片的语音停顿只落到 −45 dB，而另一片素材的配乐谷底是 −46 dB，可用窗口不到 1 dB），
> 正常演讲会被整段误判成「恒定能量」。
>
> 脚本会按本片自检区分度（人声段 spread 中位 ÷ 恒定能量段，需 ≥1.5×），
> **不可靠时明说并整体降级**，只给一条总说明加一行待判断段落清单。
> 遇到这个提示就按它给的段落人工判断，**别硬套下面的判据**。

## 判断一：这段到底有没有独立画外音

**不能只看转写稿有没有文本就下结论**，也不能只看「听起来像不像配音」。要两个证据互相印证。

### 证据 A：音频包络

抽 0.1s 窗的 RMS（dB），看能量随时间怎么变：

| 形态 | 结论 |
|------|------|
| 能量在 −18 到 −70 dB 之间正常起伏，**有清晰的句间停顿** | **现场人声**（演讲人自己解说）→ 没有第二路画外音可插 |
| **长时间（≥60s）恒定能量、无任何停顿** | **配乐 / 会场底噪** → 没有画外音 |
| 有独立文本，且时间窗能对上 | 真画外音 → 插入 |

**一个分不出来的坑：人声叠在掌声 / 配乐上。** 主持人串场常常是「人声 + 掌声」叠在一起，
掌声把能量底噪托住，整段听起来「没有句间停顿」，转写稿里却**确实有真实文本**。
实测两段音频的动态范围几乎一样（人声叠掌声段 20.8 dB、纯配乐段 19.1 dB），
**光看包络分不出「真人声叠掌声」和「纯配乐上的幻觉」**。
所以脚本对「连续能量段里却有文本」只报可疑、**不下结论**——必须回听。
（对照：真正纯人声段的动态范围约 52 dB，与这两者明显不同。）

### 证据 B：转写稿在同一时间窗有没有文本

- 转写稿在该窗口**正好一整段空白** → 印证是纯配乐
- 转写稿只有演讲人自己的段落、没有第二路文本 → 印证是现场解说

### 为什么不能用频谱图

**频谱图在这里不具判别力**——语音和音乐底噪都是低频主导，看图看不出区别。
用能量包络的**停顿结构**判断，比看频谱可靠得多。

### 两个真实案例

- **判定无画外音（配乐）**：某段 652–714s 音频恒定 −20 dB、连续 60 秒无句间停顿；
  转写稿在 10:08–11:57 正好一整段空白。两边印证 → 该段只配乐，无画外音可插。
- **判定无画外音（现场解说）**：某段 543–576s 能量在 −18 到 −70 dB 正常起伏，
  转写稿同一窗口只有演讲人本人的三段说明、没有第二路配音 → 是演讲人现场解说。

**这类判断做完必须主动告诉用户**，说明依据（包络形态 + 转写稿印证），
不要闷着标一个「无画外音」就过去了——用户会以为你漏了。

## 判断二：裁什么范围

用户说「把这段裁出来」时，范围是有歧义的。**默认裁「PPT 共享屏」那一条带**：

- 与整理稿 PPT 列的内容范围一致，插回文档时视觉上对得上
- 每场录屏的裁剪框是稳定的，可复用

但要**在交付时说明裁的是 PPT 带而非整屏**，并说明「若要含演讲人机位的整屏版可另行重裁」——
用户可能想要的是整屏。**已有明确上下文（用户说了要整屏 / 只要页面区域）就按它执行。**

裁剪到 PPT 区域时**先验证该段布局稳定**（版式判定见 `video-to-pages.md`）。

## 裁片命令

```bash
ffmpeg -ss <起秒> -i "input.mp4" -t <时长秒> \
    -vf "crop=W:H:X:Y" \
    -c:v libx264 -preset medium -crf 20 -pix_fmt yuv420p \
    -c:a aac -movflags +faststart -y "out.mp4"
```

- `-movflags +faststart` **必须带**——否则网页 / 文档里要整个下完才能播
- 输出路径要**未被占用**，别覆盖已有片段
- 裁完用 `ffprobe` 核对时长，并**抽首尾帧肉眼确认**内容、声音、时间——
  **不能仅凭参数认定精准**

### 要精确又要快：两段式 seek

`-ss` 放在 `-i` **前**是快速但不精确（关键帧对齐，可能差 1–2 秒）；
放在 **后**精确，但要从头解码，对 GB 级大文件会超时。

**两段式同时解决这个两难**——第一次粗跳到目标前 10 秒的关键帧，第二次只解码这 10 秒就到位：

```bash
ffmpeg -ss <起秒 - 10> -i "input.mp4" -ss 10 -t <时长秒> -vf "crop=W:H:X:Y" ... -y "out.mp4"
#        └ 第一次：粗跳到附近关键帧（快）        └ 第二次：在解码流里精确 seek（准）
```

实测对 3.6GB 的文件几秒钟跑完，且起止点能精确到帧。

## 边界要**测**，不要**估**

「大概从这里开始」往往不准，而且**错半秒就可能把下一段的画面带进片尾**。
用帧差扫描把边界测出来：

- 按 **0.5 秒**步长抽帧（只裁目标区域、缩成小图如 160×40 灰度），算相邻帧的签名差异
- **差异突然变大**（比动画 / 演示期间的常态高一个数量级）的那一帧 = 内容切换点
- 连续小幅变化的区间 = 动画 / 演示本身，**不是**切换
- 粗扫定位后，在**边界附近加密查看**

裁完**必须抽首帧和末帧肉眼确认**：首帧是目标内容、末帧没有被下一段污染。

> **实测踩过的坑**：按估的时长裁了一版，末帧已经是**下一张幻灯片**了。
> 回扫帧差才发现真正的切换点在片内 37.70s，而不是估的 38.0s。
> 边界差半秒在 PPT 页上无所谓，在**动画 / 演示片段上很致命**（末帧正好是切换瞬间）。

> **另一个坑**：批量裁多个片段时，临时文件名别用 `basename` 的固定切片（如前 6 个字符）
> 当唯一键——同名前缀的文件会互相覆盖，看起来像「裁错了」。**用循环下标当唯一键。**

## 不只有「演示视频」要裁——幻灯片动画也要

除了演讲人播放的演示视频，**幻灯片上的动画**（产品发布动画、架构演化、逐帧演示）
用户也可能要单独成片。判定与裁法**完全一样**：先测边界、裁 PPT 带、
用音频包络判断有没有独立画外音。

区别在**要不要插回正文**：

- **演示视频**：按下面的「写进正文」处理
- **幻灯片动画**：这一页本身就在动，演讲人的解说**就是现场实录本身**，
  **不需要**在实录里加【播放视频】标记；只在整理稿的「说明」里注明
  裁片路径、源时间区间和时长即可

> **动画内部的变化不算片段结束**——别因为画面一直在动就以为切到下一段了。

## 写进正文

**有信息的演示配音默认保留**，并与现场解说区分。用户明确要求保留画外音文字时，照录：

```
【播放视频：`视频片段/NN-姓名-Pn-演示视频.mp4`】<br/>视频画外音：……（原文照录）
```

没有独立画外音时，只留标记并注明原因：

```
【播放视频：`视频片段/NN-姓名-Pn-演示视频.mp4`】（该段无画外音，为演讲人现场解说）
```

**注意**：这与 SKILL.md 规则 4 的默认行为（视频配音通常压缩、不展开成正文）**不同**。
只有用户**明确要求保留画外音文字**时才照录；否则按规则 4 压缩处理。

来源不清楚时标明来源；纯音乐可写「播放演示，无可辨认语音」，**前提是已经检查过**。

> ⚠️ **不要用一行「播放视频」代替独有知识或操作步骤。** 演示里讲到的、
> 正文别处没有的内容，要落进正文，不能只留一个标记。

---

## 交付时要交代的

- **来源**：原视频、原视频时间区间、裁剪范围、片段路径
- **判断依据**：包络形态 + 转写稿印证（判断一）
- **裁的是什么范围**：PPT 带还是整屏
- 片段链接**相对于最终文档**，移动交付目录后仍应有效
